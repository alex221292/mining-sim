# Mining Sim — Milestone 3.1

Песочница падающих материалов, Java 25. Нужны JDK 25, подключение к интернету при первом запуске и графическая среда.

```sh
./gradlew test
./gradlew build
./gradlew run
```

В Windows используйте `gradlew.bat` вместо `./gradlew` при необходимости. Gradle Wrapper скачает Gradle 9.2.1.

Headless-бенчмарк (без окна): `./gradlew benchmark` или `gradlew.bat benchmark` в Windows. Сценарии и результаты описаны в `docs/performance-baseline.md`; это исследовательские измерения, а не строгий микробенчмарк. Архитектура и ограничения — в `docs/architecture.md`.

Экспериментальное сравнение полного обхода и активных областей: `./gradlew activityBenchmark` (Windows: `gradlew.bat activityBenchmark`); методика, результаты и ограничения — в `docs/m2-activity.md`. По умолчанию приложение использует полный обход.

Левая кнопка мыши рисует, правая стирает; 1 — песок, 2 — вода, 3 — камень, 4 — дерево, 5 — гравий, 6 — грунт; пробел — пауза, N — один тик на паузе, C — очистить мир. Кисть заменяет существующий материал. Нажмите на поле, чтобы вернуть ему фокус клавиатуры.

Стрелки перемещают камеру, колесо мыши изменяет масштаб вокруг курсора, R сбрасывает камеру к началу мира и масштабу 2 пикселя на клетку. Масштаб ограничен диапазоном 0,5–16 пикселей на клетку. Камеру можно переместить за границы мира: снаружи виден фон, рисование там игнорируется. Кисть сохраняет радиус 3 клетки мира при любом масштабе. При масштабе меньше одного пикселя на клетку отдельные клетки могут не отображаться.

Гравий падает вниз и по диагонали, но для диагонали требует пустую клетку сбоку. Грунт падает только вертикально и удерживается камнем, деревом или грунтом снизу. Оба материала вытесняют воду при падении. Подробные правила и ограничения — в `docs/materials.md`.

Бенчмарк новых материалов: `./gradlew materialBenchmark` (Windows: `gradlew.bat materialBenchmark`); методика и замеры — в `docs/m2-material-performance.md`.

Мир 400×300 закрыт по краям. Песок падает вниз или по диагонали и тонет в воде, меняясь с ней местами; вода сначала падает вниз, затем по диагонали, затем течёт вбок; камень и дерево неподвижны. Вода ищет свободный путь к падению на расстоянии до 8 клеток и может переместиться по нему за один тик; через занятые клетки она не проходит. При отсутствии спуска вода над водой выбирает более длинный открытый участок, а на твёрдой поверхности сдвигается на одну клетку. Одна частица перемещается не более одного раза за тик. Выбор направления воспроизводим при одинаковых начальном состоянии, seed и последовательности действий. Это локальная игровая аппроксимация, не гидродинамика; некоторые колебания и неровности остаются. Сценарий бассейна и сравнение — в `docs/water-flow.md`.

Симуляция выполняется с фиксированным шагом 60 Гц и ограничением на догоняющие тики; вся работа с миром и интерфейсом происходит в потоке Swing. FPS и TPS отображаются отдельно.

Overlay показывает длительность последнего тика и среднее/максимум по последним 120 выполненным тикам в миллисекундах; до первого тика значения равны нулю. На паузе окно не обновляется, одиночный шаг учитывается. FPS — нарисованные кадры в секунду, TPS — выполненные тики в секунду; время тика не включает отрисовку.
