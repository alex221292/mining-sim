# M4.5b.4c — prospective assembly support

Group placement is prepared without modifying World. For candidate cells above existing settled parts, the planner analyzes the affected vertical-contact components with the candidate cells as hypothetical upper contact intervals. Existing settled parts must all pass the conservative support check with these additional intervals; candidates must separately satisfy the vertical force/moment check. The existing group publication and revision checks remain authoritative. Analysis consumes the group work budget and refuses incomplete, stale or over-budget results. This is a conservative sufficient check, not friction, contact strength or a general equilibrium solver; stable configurations may be rejected.

Automatic detachment checks ordinary STONE components above settled supports without creating cross-ownership bonds. It checks their center of mass and analyzes the contacted settled components with the existing upper contacts. Pending or over-budget support analysis defers extraction. The per-tick support work is bounded separately from the topology budget. Side contacts alone do not qualify.

F3 displays cached completed assembly components, supported settled parts, vertical support contacts, dirty work, separate last settling/support rejections and accumulated assembly analysis time. A pending marker means the cached counts are incomplete; no World scan is performed during repaint. Assembly IDs are the minimum settled ID of each analyzed vertical-contact component. A change invalidates affected cached components. Ordinary STONE is not given settled ownership or an inter-owner bond. Analysis and settling remain bounded, and unchanged settled scenes are not continually reanalyzed. GUI manual acceptance has not been performed.

Headless tests cover three sequential rocks, bridges, destabilizing upper loads, two independent assemblies, side contact, support loss, sand, budget exhaustion, veto and stale prepared plans. A 64×64 fixture puts the 134/134/526 rigid stack above a removable 54-cell settled support, settles it, removes that support, reactivates all three and settles them again; cell count, mass and substance are checked. The support itself is explicitly removed matter. This does not change the `.msim` world-only format or solve general STONE strength, arches, CCD or friction.

## Measurements

OpenJDK 25.0.5+8-LTS, Windows, one JVM, 20×20, two warmups and ten measured runs; `java -cp build/classes/java/main miningsim.benchmark.ProspectiveSupportBenchmark 10`. Mean / nearest-rank p95 in ms: first preparation 0.204 / 0.270, second 0.238 / 0.309, third 0.251 / 0.341 (10 each); cascade tick 0.352 / 0.582 (10); unchanged three-rock tick 0.011 / 0.018 (1,200). The same invocation additionally uses one 128×64 run with 20 single-cell settled rocks: unchanged tick 0.017 / 0.017 (120 ticks), tick after STONE addition 0.052 / 0.085 (10 ticks), and three ten-cell sand batches 0.239 / 0.394 (180 ticks, including subsequent motion of newly added STONE). The dense scene is one run, not ten independent runs. For the pre-existing 64×64 134/134/526 fixture, `HeadlessLifecycleBenchmark 10` measured initial settling preparation 5.822 / 14.341 ms and commit 0.696 / 0.726 ms (10 each); this benchmark does not measure its full lifecycle. These wall-clock observations are not FPS or guarantees.
