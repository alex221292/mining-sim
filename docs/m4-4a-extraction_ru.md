# M4.4a — извлечение неподвижных фрагментов

`ExtractionPlanner.prepare(world, connectivity, x, y, maxCells)` читает завершённую связность и возвращает `READY` с неизменяемым списком координат, ревизией, ID компонента, нормализованным `FragmentDescriptor` и началом в мире. Ожидающая топология, некаменная клетка, опирающийся или слишком большой компонент отклоняются. Планирование не меняет владельцев. Извлекается только generic STONE с соответствием `SubstanceRegistry.STONE` (2500 кг/м³); GRAVEL и bedrock не извлекаются. Компонент с прямым путём к bedrock не допускается; топологическая опора не доказывает механической устойчивости.

`ExtractionCommit.commit(plan, registry)` отклоняет устаревшую ревизию и активный обход связей, заново проверяет полный текущий компонент, геометрию, размещение, вещество и массу, заранее проверяет вместимость, ID, переполнение и готовит полное новое состояние реестра. Ожидаемые отказы возвращают статус без изменений владельцев. Миром и реестром владеет один поток симуляции; другой код не должен одновременно или повторно входя в транзакцию читать или менять их. Это не межпоточная транзакция и не транзакция сохранения.

`World.replaceAllIfMatches` до записи проверяет координаты, ожидаемые/новые материалы и дубли; защищает bedrock и упорядочивает изменения по y/x. Пустое изменение не генерирует событие. Для извлечения `FragmentRegistry.Prepared` содержит заранее выделенное неизменяемое состояние реестра и резервирование с проверкой ревизии; мир до записи проверяет точное совпадение всех изменений STONE→AIR с геометрией фрагмента generic stone. Затем мир выполняет проверенные записи клеток, публикует подготовленное состояние реестра присваиваниями без выделения памяти и только после этого один раз вызывает `ChangeSink.changedBatch` с неизменяемым списком. Таким образом, корректный callback видит обоих полных владельцев. Между проверкой и публикацией при однопоточном невложенном контракте не выполняется другой код. Как и прежде, callbacks не должны выбрасывать исключения или менять мир; восстановление после отказа VM или нарушения контракта не обещается. Обычный `set` сохраняет прежнее уведомление отдельной клетки.

`RockConnectivity.changedBatch` очищает только биты разрывов у затронутых клеток, обновляет incarnation изменённых клеток, один раз увеличивает ревизию и помечает компоненты ожидающими. Удалённые разрывы и incarnation повреждений сохраняются; `invalidated()` не используется. Между извлечениями компонентов нужно пересчитать связность; старые механические снимки после смены ревизии недействительны. Callback не выполняет flood-fill или решение механики.

`RockFragment` содержит монотонный ID реестра, неизменяемый дескриптор, начало в координатах клеток мира, нулевой угол и исходный ID компонента. Мировая координата `(originX+localX, originY+localY)` совпадает с исходной клеткой; скачка положения нет. Одна клетка STONE — 2 500 000 мг, поэтому `статический камень до = статический камень после + масса нового фрагмента`. Масса реестра проверяет переполнение целых чисел. Фрагмент владеет материалом отдельно от World; рендерер накладывает неподвижные окрашенные клетки. Нет движения, коллизий, осыпи, инвентаря или сохранения. Текущий рендерер не запрещает последующее рисование или попадание клеточных материалов в те же позиции, что неподвижный фрагмент; коллизии и занятость остаются будущей работой, текущая визуализация ещё не физическое тело. Команда World.clear также не очищает реестр фрагментов; для полного сброса перезагрузите сцену.

В эталонных сценах выберите компонент средней кнопкой, дождитесь статуса `UNSUPPORTED`, затем F5 явно извлекает выбранный компонент. Это сохраняет возможность увидеть диагностику и исключает автоматическое извлечение в обычном мире. Одно извлечение переводит связность в pending; перед выбором и извлечением следующего дождитесь структурного тика. Исходная выбранная клетка становится AIR, после пересчёта HUD показывает NO SELECTION. F4 создаёт новый реестр и сбрасывает ID. Фрагменты отображаются на исходных координатах через `Camera2D`; графическое взаимодействие в этой среде вручную не проверялось.

`gradlew.bat test build` проверяет отказы batch, одно полное уведомление, сохранение удалённого разрыва, incarnation, устаревшие планы/полный реестр, владение/массу, детерминированные ID, повторное использование подготовленного состояния, выбор и сброс контроллера. `gradlew.bat fragmentExtractionBenchmark`, Windows 11 Java 25, один исследовательский запуск: для 1/6/32/64 клеток планирование 25,525/0,335/0,767/0,544 мс, проверка+commit 9,854/0,458/0,739/0,797 мс, перестроение связности 0,028/0,030/0,030/0,031 мс, снимок 0,000040/0,000022/0,000024/0,000022 мс; шесть клеток образуют Г-форму. Последовательное извлечение 16 отдельных клеток с пересчётами заняло 4,610 мс. Первое измерение включает JIT/загрузку классов; это исследовательские результаты без обещания производительности полного мира. M4.4b предстоит решить движение, коллизии/занятость и сохранение до появления полноценных физических тел.
