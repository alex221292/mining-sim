# M4.1: коренная порода и граница мутаций

`World(width, height)` создаёт мир `LEGACY`; явный `World(width, height, World.Mode.BEDROCK_ENABLED)` создаёт мир с полностью неразрушимым нижним рядом BEDROCK (статический ID 7). Обычный `set` не создаёт коренную породу ни в одном режиме. Интерактивная песочница использует второй режим; нижний ряд legacy-мира не ограничен. API миграции нет.

`set` проверяет границы и null и возвращает `CHANGED`, `NO_OP` или `REJECTED`. Только реальные изменения отмечают активность и синхронно вызывают необязательный `ChangeSink.changed(x,y,previousId,nextId)` в порядке записей. При подключении потребителя вызывается `invalidated()` для первоначального перестроения; `clear()` вызывает его один раз после массовой операции, даже для пустого мира. При инвалидации потребитель перестраивает состояние по миру. Ограниченной очереди и хранения событий нет: единственный потребитель должен синхронно обработать каждый вызов, не выбрасывать исключений и не изменять мир. Приложение владеет миром в одном потоке. Очистка сохраняет коренную породу, не очищая нижний ряд; legacy-очистка удаляет все клетки. Оба варианта сохраняют прежнюю инвалидацию всех плиток активности. Отдельной операции reset нет.

MSIM v1 принимает только ID 0–6, загружается как LEGACY и сохраняет прежние кодирование и CRC. Сохранение BEDROCK_ENABLED через любой API v1 завершается ошибкой до записи байтов и изменения файла; UI показывает ошибку ввода-вывода. Legacy-файлы с занятым нижним рядом не меняются. Формата v2 и преобразования нет, поэтому новые интерактивные миры пока невозможно сохранить.

Исследовательский `gradlew.bat benchmark`, Java 25.0.5, Windows 11, seed 12345, пять серий после прогрева: плотный FULL_SCAN 1600×900 до среднее/медиана/p95 19,268/19,219/20,386 мс, после 19,241/19,213/19,752 мс. При 400×300 active: 1,509/1,508/1,558 против 1,749/1,748/1,865 мс. Пустые и статические 1600×900 выросли примерно с 3,0 до 3,8 мс; эти шумные однократные измерения не выделяют стоимость мутаций. Потребитель не был подключён. Это не контролируемый микробенчмарк; для выяснения причин нужны повторные измерения и профилирование.
