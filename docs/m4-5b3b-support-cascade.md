# M4.5b.3b — headless support-loss cascades

`SettledSupportCoordinator` is an explicit single-owner headless service; call `step(generation)` between simulation ticks. It is not installed in Swing. `RockConnectivity` remains the sole World change sink and forwards STONE and ownership changes internally; sand and water movement does not dirty support. Initial discovery is incremental. Later changes dirty neighboring settled IDs, and the coordinator incrementally analyzes the affected vertical-contact component. Terrain, topology or ownership revisions invalidate unfinished analysis; no partial result is published. LEGACY mode is a no-op.

The conservative, frictionless vertical model uses downward contacts, a strict center-of-mass support interval and worst-case upper-contact intervals; lateral contact is not support. An ordinary STONE cell is accepted as an immovable foundation only when directly supported by BEDROCK, consistent with the structural anchor rule. Damaged settled rocks are not certified stable. This is not a bond-strength, pressure, friction, impact or FEM analysis; uncertain configurations are not declared stable. Different settled IDs remain separate bonds and materials.

An unsupported dependent closure is transferred in one prepared group batch. Veto, precommit errors, stale dependencies and occupancy conflicts publish no partial group. Body IDs are assigned in ascending settled-ID order; cell count, substance, integer mass and settled-to-body provenance are preserved. Once a support coordinator is attached, direct single/group reactivation is refused so callers cannot bypass cascade closure. While analysis or cleanup is pending, all settled transitions and settled-support proofs are conservatively quarantined; cellular simulation is not paused. This intentionally blocks even unrelated settled transitions until the pending analysis finishes. Callbacks remain single-owner, non-reentrant and non-throwing.

Limits are explicit: per-tick historical-ID scanning and graph work, maximum graph IDs/cells, group IDs/cells, and one preparation attempt per `step` (never exceeding `attemptsPerTick`). Occupancy rebuilding uses the caller's `RigidBodyOccupancyIndex.Limits`. `Limits.measuredDefaults()` is an initial headless configuration exercised by the fixtures below, not a real-time guarantee. Per-tick work exhaustion returns `IN_PROGRESS` with the dirty queue retained. A hard graph/group/occupancy limit returns `LIMIT` without publication; the caller can raise limits with `setLimits` and continue. Veto, invalid geometry or unsafe occupancy returns `BLOCKED`, retains dirty work and does not stop cellular ticks. No unresolved component may be used as certified support.

## Verification

Headless tests cover group atomicity, observers, veto and precommit exception, stale World/generation and occupancy failures, support removal, independent support, side contacts, unverified ordinary STONE, budgeted continuation, mutation restart, replay, repeated settling/reactivation, LEGACY mode and cellular progress. For the 134/134/526 reference, the test first settles the original scene, then copies its exact settled shapes one cell upward into a separate 64×64 world with a removable ordinary-STONE layer above immutable BEDROCK. Removing that layer triggers a single 794-cell, three-body cascade; the bodies fall and contact BEDROCK. This is not an in-place removal from the original fixture.
