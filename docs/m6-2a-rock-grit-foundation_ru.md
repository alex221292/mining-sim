# M6.2a — основа каменной крошки

Статус: ожидает ручной GUI-приёмки. M6.2b, атомарное преобразование блока в крошку, не реализован. При 100% добычи блок остаётся на месте. Генерация и правила опоры не изменены.

## Идентичность, хранение и сохранение

ID материалов 0–10 сохранены; ID 11–14 представляют STONE, GRANITE, LIMESTONE и MARBLE в форме `GRIT`. `rockSubstance()` и `rockForm()` раздельно описывают вещество и форму. Крошка сыпучая, не является fixed rock, не имеет block ID, собственной структурной прочности и не служит структурной опорой. Обычный гравий не получает идентичность породы.

В каждом чанке остаётся массив байтовых ID. Массив ссылок на состав создаётся лениво только в чанке с непустой рудой крошки; пустые записи равны null. Неизменяемые `OreComposition` могут разделяться клетками. При удалении последней непустой записи массив чанка освобождается; замена и очистка удаляют метаданные. Глобальной таблицы интернирования с неограниченным сроком жизни нет. Массив заполненного чанка содержит 4096 ссылок (обычно около 16 КиБ при сжатых ссылках, без заголовка; зависит от JVM): это оценка, а не замер heap. Обычные чанки не выделяют массив руды. Во время движения концентрации не вычисляются.

Крошка использует правила песка: падение, диагональное осыпание и обмен с водой; существующие правила гравия и грунта не меняются. При движении материал и состав обмениваются до уведомления наблюдателей, в том числе через границу чанка. Исторический путь rigid recovery отказывает для мира с крошкой вместо переноса неполных метаданных; в fixed-block gameplay он не используется. Разные составы не смешиваются. Кисть создаёт крошку без руды. Доля компонента задаётся целым числом ppm (1 ppm = 0,0001%); существующая валидация требует уникальные стабильные Ore ID, положительные значения и сумму не более 1 000 000 ppm.

Активная клеточная модель не задаёт физическую массу клеток. Её контракт — сохранение числа клеток каждого вещества и точной суммы ppm каждого компонента для равных объёмов. Будущее преобразование блока 4×4 или 8×8 должно создать 16 или 64 клетки того же вещества с **неизменённой** концентрацией ppm в каждой, не делить ppm на число клеток. Это дискретный инвариант объёма и состава, а не полноценная симуляция массы; новые плотности и правила упаковки не вводятся.

## Управление и диагностика

Обычные цифры: 2 WATER, 3 STONE fixed block, 4 WOOD, 7 GRANITE fixed block, 8 LIMESTONE fixed block, 9 MARBLE fixed block. Shift+1 SAND, Shift+3 STONE GRIT, Shift+5 GRAVEL, Shift+6 SOIL, Shift+7 GRANITE GRIT, Shift+8 LIMESTONE GRIT, Shift+9 MARBLE GRIT. Обычные 1/5/6 и Shift+2/4 не назначены. Используются key code и модификатор Shift, а не символ раскладки. F3 показывает форму, вещество и руду в ppm и процентах; F9 подсвечивает фактический состав клеток. Цикл F4 сохраняет прежние сцены и добавляет остановленную сцену с четырьмя породами, водой, сыпучими материалами, блоками и соседними клетками с пустым составом / IRON 120000 ppm / IRON 120000 + COPPER 25000 + SILVER 80 + GOLD 5 ppm. Поддерживаются оба размера блоков.

## Persistence

MSIM v5 сохраняет заголовок v4, клетки, записи блоков и независимый раздел их руды. Перед CRC32 добавлены детерминированная палитра составов и разреженные записи клеток GRIT. Числа big-endian: знаковый int размера палитры, для каждого состава беззнаковый byte числа компонентов и пары беззнаковый byte Ore ID / знаковый int ppm; затем знаковый int числа клеток и пары знаковый int row-major индекса клетки / знаковый int ссылки на палитру с единицы. Пустой состав не записывается. Палитра упорядочена по первому появлению при row-major обходе. CRC и атомарная замена файла fixed session сохранены. Границы, материалы, руды, составы, ownership, повторы и ссылки проверяются до публикации. Чтение v1–v4 сохраняет историческую семантику; старые версии отвергают новые ID. V1 не записывает крошку. Прогресс добычи и RNG не сохраняются.

Исторические тесты, явно ожидавшие версию writer v4, обновлены для v5 с сохранением проверок старых форматов. GUI не запускался.
