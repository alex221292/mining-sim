# M4.7 — сохранение fixed-block в MSIM v2

Ctrl+S сохраняет fixed-block-сессию как MSIM v2; Ctrl+O полностью проверяет новую сессию до замены текущей и восстанавливает размер 4×4 или 8×8. Пауза и кисть сохраняются, камера сбрасывается. Запись синхронна на потоке-владельце Swing между тиками. Если команды ввода ожидают обработки, сохранение отклоняется без их применения: продолжите симуляцию или выполните одиночный шаг и повторите. Временный pinned записывается и проверяется, но при загрузке снимается: состояние ввода мыши не переносится, и блок начинает обычную задержку падения. Старый MSIM v1 загружается как отдельная LEGACY-сессия, без преобразования произвольного STONE в блоки. Поведение и формат v1 в `WorldIO` не менялись.

## Бинарный формат

Все многобайтовые целые числа — big-endian; вызывающий код владеет потоками `.msim`. CRC32 — IEEE CRC-32 по всем предыдущим байтам; контрольная сумма — беззнаковый uint32, лишние байты запрещены.

| Смещение | Байты | Поле |
|---:|---:|---|
| 0 | 4 | ASCII `MSIM` |
| 4 | 4 | int32 версия = 2 |
| 8 | 4 | int32 ширина |
| 12 | 4 | int32 высота |
| 16 | 4 | int32 режим мира = 1 (BEDROCK_ENABLED) |
| 20 | 4 | int32 размер блока, 4 или 8 |
| 24 | 4 | int32 количество блоков |
| 28 | 8 | int64 следующий ID блока |
| 36 | ширина × высота | беззнаковые ID материалов, построчно |
| 36 + клетки | количество × 20 | записи блоков, при записи в порядке возрастания ID |
| 36 + клетки + 20 × количество | 4 | CRC32 |

Запись блока: положительный int64 ID, int32 x, int32 y, uint8 состояние (0 STATIC, 1 FALLING), uint8 счётчик ожидания (0–8), uint8 pinned (0/1), uint8 вещество (0 STONE). Размеры мира — 1–4096, произведение не более 4 194 304; число блоков не выше cells/(size²). ID уникальны, следующий ID положителен и больше всех живых ID; координаты выровнены по нижней сетке, находятся в границах и не пересекаются. Все клетки блоков — STONE, неучтённый STONE запрещён; BEDROCK расположен ровно на последней строке. FALLING не может быть pinned или иметь ненулевой счётчик ожидания. Ошибки записей, размеров, ID материалов, суммы, версии, усечение и лишние данные вызывают `IOException`.

Записываются только авторитетное состояние блоков и клетки World; диагностика, камера, UI и производные кэши не сериализуются. Состояние RNG клеточной симуляции **не сохраняется**: загрузка создаёт симуляцию с seed 12345. Поэтому загруженная сцена продолжает работу с сохранённым веществом и состоянием блоков, но **не обязана совпадать с непрерывным детерминированным replay**. Одинаковые файлы и команды детерминированно воспроизводятся от точки загрузки. Java-сериализация объектов для формата файла не используется.

Запись по пути выполняется в соседний временный файл с обязательной атомарной заменой; если файловая система её не поддерживает, операция завершается ошибкой без потенциально небезопасного fallback. Замена активной сессии происходит только после проверки входных данных. CRC32 обнаруживает случайное повреждение, но не защищает от злонамеренной подмены. Крупные файлы синхронно задерживают UI; фонового I/O и сжатия нет.

## Ручная Swing-приёмка

Для каждого размера нарисуйте стопку и воду, поставьте паузу во время задержки и сохраните через Ctrl+S. Измените сцену, затем загрузите Ctrl+O; проверьте размер блоков, форму, воду, паузу, одиночный шаг и последующее падение. Повторите во время падения блока. Загрузите файл v1 и проверьте режим LEGACY и редактируемый STONE, затем попробуйте повреждённый файл и убедитесь, что текущая сцена не изменилась. Проверьте подтверждения перезаписи и замены сцены через F7. GUI проверяет только пользователь.
