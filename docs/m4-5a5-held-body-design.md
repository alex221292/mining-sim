# M4.5a.5-design — HELD rigid-body contract

**Design only; not implemented or safety-proven.** Baseline `4b48859db4ca474b09c654b8913a9e2b098a8a4c`. HELD is a proposed temporary pre-solve constraint, not a material, a new fragment type, SLEEPING, CCD, or a promise that every obstruction can be resolved. Positions use cells (1 cell = 0.1 m), velocity m/s, angular velocity rad/s, and fixed ticks 1/60 s. Names below are existing unless explicitly marked proposed. All mutation remains on the simulation owner thread.

## Current architecture and limits

* `InteractiveSession.tick()` drains commands, executes structural/automatic work, then `coupled.step()` and, on success, `coupled.stepCells(simulation)`. `resume()` resets the BLOCKED latch. On eligible SWEPT failure it calls `stepCellsAfterSweepRollback`; three stalled attempts latch BLOCKED. Commands and structural work precede the coupled checkpoint and are not rolled back by it.
* `RigidBodySystem.step()` synchronizes registry membership and saves body states, diagnostics, revisions and solver counters. `sharedStep()` calls `wakeNearby`, chooses a shared bounded microstep schedule, then `RigidBody.integrate()` applies gravity and advances position and angle. `StaticCollisionQuery.query()` is discrete and, with `DISPLACE_GRANULAR`, treats STONE/WOOD/BEDROCK and boundaries as solid, not granular matter. `StaticContactSolver.prepare()` and `Prepared.iterate()` apply static impulses; `correctPosition()` translates the body. `BodyCollisionQuery.query()` produces deterministic ID-ordered actual-cell SAT contacts, normal from lower to higher ID; `BodyContactSolver.prepare()`/`Prepared.iterate()` use finite inverse masses and `RigidBody.applyImpulse()`. `sharedStep()` separately applies inverse-mass-weighted pair position corrections by `translate()`.
* `wakeAll()` and `wakeNearby()` wake sleepers, including in response to edits and approaches; `updateIslandSleep()` constructs a transient union-find from end contacts after support propagation, not a complete trajectory dependency graph. HELD cannot be implemented by setting `sleeping`, by removing a body from `bodies()`, or by restoring its pose after solving other bodies.
* `CoupledSimulationStep.step()` captures `physics.coupledCheckpoint()`, attaches `setCoupledTrace`, calls `physics.step()`, `occupancy.prepare()`, `rejectUnresolvedSweep()`, `CellularDisplacementPlanner.plan()`, then `World.replaceAllAndPublishOccupancy()`. The prepared occupancy publishes a snapshot for **all** bodies; it records multiple memberships, which alone do not establish geometric body overlap. `rejectUnresolvedSweep()` checks sampled/interpolated traced poses, with work limits, and throws private `SweepObstruction` with coordinates in fields and material/body only in the message. It is an existing bounded sampled check, **not a continuous-collision proof**. Its target-occupancy exception and current material classification must not be silently changed. A stationary HELD trace introduces no new path, but neither HELD nor this design proves continuous safety of other bodies.
* On pre-publication failure the coupled catch restores `CoupledCheckpoint` only if World revision is unchanged. World batches preflight and publish occupancy; `World.ChangeSink` callbacks must not throw. Current `stepCells()` runs **after** coupled publication and is expressly non-transactional; a failure there cannot roll back the coupled commit. The exceptional `Simulation.stepRecoveryAtomically()` uses a bounded shadow FULL_SCAN and batch, not the ordinary path. `CoupledDiagnosticsOverlay.render()` reads diagnostics, failure stage, counts and recovery status; it does not step physics. F3 currently has no HELD status.

## Proposed state and lifecycle

Proposed owner-thread `HoldRecord`, keyed by stable body ID in deterministic order, holds validated pose, reason and typed obstruction (cell, material, body ID), entry tick, observed World mutation and rigid-terrain revisions, occupancy generation, hold age, next eligible retry tick, retry/backoff and pending-release reasons. Membership and all fields are transactional. Registry/descriptor/substance, physical mass and inertia never change; body remains visible, inspectable, in occupancy and pair queries. Existing cell selection/extraction concerns World STONE, not already extracted rigid bodies: no new held-body selection/extraction API is implied. A future explicit body removal uses existing owner-thread registry/occupancy transaction and removes its hold atomically; if unavailable, reject the request, never leave a dangling ID.

At ACTIVE → HELD, restore the complete checkpoint first; retain pose exactly, **zero both linear components and angular velocity**, clear the sleep window, and do not later replay the old velocity. This deliberately dissipates kinetic energy; it cannot inject a stored stale impulse on release. The failed trial's velocities may be kept only in bounded diagnostics, never authoritative motion. HELD has zero effective contact-point velocity, ignores gravity, integration, impulses and correction, but may support/push other bodies via constraint reaction. The hold is not an indefinitely justified physical anchor: it is an explicit, visible gameplay approximation that can dissipate momentum and artificially support a stack.

HELD → ACTIVE is a proposed trial from the next validated checkpoint with zero linear/angular velocity and cleared sleep history; release is published only if the entire trial passes. A failed release leaves the old hold intact, with deterministic bounded backoff. HELD → SLEEPING is not direct: first successfully release to ACTIVE, then use the normal supported quiet-window rule. A normal ACTIVE/SLEEPING body whose support changes follows existing wake/solve rules. HELD → removed is atomic as above. Resets retire all hold state with the session; no save format change is proposed.

Queue (not execute mid-solver) release revalidation on obstruction removal/change, relevant owner-thread edits including terrain/support, neighbor membership/contact changes, support loss, or an impact. Detect relevant events through existing owner-thread operations and bounded contact/occupancy observations, not a competing `World.ChangeSink`; if locality cannot be established, conservatively queue a bounded global invalidation, not silently ignore it. Also revalidate periodically in fixed ticks, not wall time. After committed cellular motion, inspect the recorded obstruction cell and queue for the **next** tick; checking that cell alone is only a trigger, never proof that the entire trajectory is clear. Before a trial recheck revisions/membership; release always needs full validation. At most one eligible release per tick, stable ID round-robin; event coalescing plus backoff prevents hold/release oscillation. An impact is solved against HELD now and queues a future release; it must not unhold midway through a solve. Persistent failures remain HELD and visible, not claimed resolved.

## Proposed solver contract

At the start of a complete trial pass an immutable candidate HELD set to the integration and solver paths (proposed APIs). `sharedStep()` excludes held bodies from integration, gravity, sleep scheduling and static velocity/position response; validates their initial static overlaps and keeps them in `queryBodies()`. `wakeNearby`/`wakeAll` must not change HELD; active/sleeping participants otherwise retain normal wake behavior. The all-sleeping fast path needs an explicit HELD-aware proof, while the empty-HELD branch must preserve today's fast path and ordering. Support propagation must treat HELD as an immovable support source for others, while separately queueing its own support-loss revalidation; it must not make a HELD body normally sleep.

For `BodyContactSolver` use solver-local effective inverse mass and inverse inertia zero for HELD, physical inverse values for ACTIVE. A held contact has zero surface velocity including angular contribution. Use existing A→B normal, relative velocity B−A and sequential contact ordering; apply normal and bounded Coulomb tangent impulses only to movable participants, with existing restitution config/threshold relative to the held zero velocity. Guard finite denominators; do not divide by zero. Multiple contacts are processed in existing deterministic order within existing iteration and aggregate contact budgets. Pair correction in `sharedStep()` uses the same effective inverse masses: all correction goes to the movable participant; neither HELD pose nor angle changes. HELD–HELD has no impulse/correction and must be checked for invalid penetration rather than divide by zero; reject contradictory or excessive initial overlap. HELD–SLEEPING may remain quiet only if valid and undisturbed; an approaching/impacted sleeper follows normal wake propagation and is then solved as ACTIVE against HELD. HELD–ACTIVE is solved every relevant microstep. Do not modify persistent mass, inertia, descriptor or SAT geometry.

The present solver is discrete and iterative, with slop and capped correction. M4.5a.5b must define and test an explicit maximum allowed residual penetration against HELD and other bodies, initial-overlap handling, and post-solve validation; current `0.01`-cell correction slop alone does not prove no tunnelling or convergence. Reject rather than accept an unverified candidate. No universal continuous body-body collision guarantee is asserted.

## Proposed coupled retry and publication

At the boundary after commands/structural work, capture complete validated physics and hold checkpoint, published occupancy identity/generation, World mutation and rigid-terrain revisions and coupled/session diagnostics. Normal trial uses existing holds. On a typed SWEPT obstruction, including proposed structured body ID/material/coordinates rather than parsing a message, discard all prepared data and restore the **whole** checkpoint. Add the failing body to a trial-only hold set, then rerun the **whole** physics tick from that checkpoint with the set installed before integration. Do not combine previously solved trajectories with restored bodies. Retry additional distinct SWEPT offenders in deterministic failure order; duplicate offender, invalid ID, non-SWEPT error, or budget exhaustion fails explicitly. Every retry starts from the same checkpoint; trace and counters are reset and charged cumulatively.

For each candidate: keep held pose unchanged, run all contacts and static checks, validate finite states and residual overlap, prepare complete occupancy once, run the unchanged SWEPT validator for every traced body, plan displacement, validate membership/revisions and no forbidden material/occupancy overlap. Only then preflight and publish the complete World batch, occupancy, physics and HELD metadata as one owner-thread commit. Metadata and diagnostics must be preallocated and publication non-throwing; observers/callbacks cannot see a hybrid. `World.replaceAllAndPublishOccupancy()` alone does not publish hold metadata; a proposed composite commit or equivalent extension is required, subject to existing non-throwing callback contract. No retry after a partial World publication. A changed revision or stale prepared snapshot rejects the trial.

Cellular simulation is a **separate** phase after this coupled commit, against its published complete occupancy, so held rock remains an obstacle to SAND/GRAVEL/SOIL/WATER. For HELD-enabled operation, require a proposed bounded atomic cellular preparation and publication (including RNG) or explicitly report `CELLULAR_FAILED` without claiming the cellular step ran; current `stepCells()` is not sufficient. A failed cellular preparation preserves its own pre-phase state, **not** a rollback of an already committed physics phase. If one atomic physics-plus-cellular transaction is later demanded, it needs additional World/RNG staging and is not provided by the current API. Check obstruction changes after successful cellular publication and queue next-tick release. Matter counts and substance identity must be conserved; no World cell inside published rigid occupancy may contain displaceable matter after displacement/cellular publication.

## Checkpoint, failure and budgets

Proposed checkpoint includes all `RigidBody.State` fields (pose, velocities, sleeping, sleep counters/anchors), body membership and registry identity/revision, observed terrain revision and successful IDs, solver counters/profile and interaction/motion diagnostics, HELD records and release queue/backoff, coupling diagnostics/failure stage/counters, occupancy snapshot identity/revision/generation, World mutation and terrain revisions, and cellular RNG/state if cellular preparation is attempted. Scratch traces, temporary constraints/contact accumulators and work counters are discarded/reconstructed deterministically. Current `CoupledCheckpoint` restores body membership/states, published physics diagnostics, IDs, revision and `StaticContactSolver.CounterState`; solver profiling scratch, coupled/session diagnostics, HELD and cellular state need explicit treatment rather than assumed coverage.

SWEPT, occupancy or plan failure, budget exhaustion and injected exceptions **before publication** restore the original validated checkpoint and discard all candidate holds, with no World/occupancy publication; publish separate bounded failure diagnostics only after rollback. If the owner-thread invariant or no-throw publication callback contract is violated, current code cannot guarantee rollback after World writes: stop and report invariant failure, do not claim atomicity. Phase-local cellular failures follow the separate-phase rule above. Unexpected exceptions are not converted into success.

Initial proposed limits, subject to measurement and configuration review: at most 4 newly held bodies and 4 full re-simulations per tick after the initial attempt; at most 64 simultaneous holds; at most 1 release trial per tick with minimum 30-tick backoff and periodic retry every 120 committed ticks; at most 5 occupancy preparations total including initial trial; 64 diagnostic events in a bounded ring, coalescing overflow. No full World scan per held body. Each trial obeys existing `MotionConfig` defaults (128 microsteps/body, 4096 total), `InteractionConfig` aggregate limits (1M pairs, 10M checks, 1M raw/reduced contacts and wake work) and occupancy limits (10M area checks, 4M memberships); HELD contacts consume the same budgets, not a free pool. Aggregate hard limits across trials: 5× each existing per-trial limit, including sweep/planning limits; preflight/decrement remaining work before each operation, fail explicitly on exhaustion. A release trial shares, not adds to, these attempt limits.

Worst case is five whole bounded physics/occupancy/sweep/planning attempts, not five isolated bodies' cost; with current limits this can still be far too slow for an interactive frame. Checkpoint/hold storage is O(bodies + holds), at most 64 bounded records; occupancy scratch can reach O(occupied cells + memberships), trace storage O(recorded poses), and atomic cellular shadow O(world cells), all requiring explicit byte/allocation limits in addition to operation counts. Do not multiply retained snapshots/traces by attempt count: discard before retry. Exact bytes and elapsed time are unmeasured; allocation failure is not assumed safely recoverable. Budget failure restores the checkpoint and reports it; it may still globally block rather than freeze every body or pretend a tick succeeded.

Diagnostics must distinguish normal coupled success, one/multiple HELD and reason/age/retry, successful cellular-only fallback, cellular failure, release pending, and genuine global BLOCKED with stage, body/cell and budget. F3 shows bounded records and separately counts committed coupled/cellular steps and attempts; F6 requests a bounded retry, not guaranteed release. Existing cellular-only fallback is allowed only after its current verified rollback conditions; it cannot be advertised as a successful coupled tick. Invalid initial overlap, incompatible contacts, excessive contact graph/work, stale World/occupancy, or exhausted retries fail closed.

## Deterministic headless acceptance matrix for M4.5a.5b

Each test compares replay snapshots and validates finite values, exact held pose/identity, occupancy membership, material counts and bounded work where applicable. Tolerances for iterative contacts must be justified and no larger than the explicitly approved residual limit.

| Case | Required assertion |
|---|---|
| One obstructed moving body | Prove original SWEEP first; retry holds at exact pre-tick pose, preserves material and commits no partial trial. |
| Two independent moving bodies | Obstructed held; independent advances; unchanged original ID/mass; no global freeze. |
| Two contacting bodies | Whole re-solve has consistent impulses, no excessive overlap or post-hoc pose patch. |
| Three-body stack | Held lower body supports upper bodies within residual limit; no unexpected energy growth. |
| HELD supports ACTIVE | Gravity/contact response acts on ACTIVE; HELD pose and velocity stay exact. |
| ACTIVE impacts HELD | Finite bounded response, HELD unchanged, impact queues release rather than changing state mid-step. |
| HELD–HELD | No zero denominator; valid contact stable, invalid overlap rejects atomically. |
| HELD–SLEEPING | Quiet pair stays quiet when valid; impact wakes sleeper without releasing held participant mid-solve. |
| Rotation while HELD | Nonzero pre-entry omega is discarded; pose/angle remain exact over repeated ticks. |
| SAND removal / cellular removal | Queue revalidation after committed cell change; successful full release resumes from zero velocity. |
| World edit / support removal | Invalidation is deterministic; release trial or explicit bounded defer, never silent permanent hold; ordinary sleepers wake correctly. |
| Repeated obstruction | Hundreds of committed ticks: held remains visible, independent bodies and free cellular materials advance, retries/backoff bounded. |
| Multiple independent SWEPT failures | Restore original checkpoint on each trial; bounded set expansion or explicit budget failure with exact rollback. |
| Replay | Compare complete World, RNG continuation, bodies, hold queue, revisions, occupancy and published diagnostics across runs. |
| Injected failures | At checkpoint, solver, trace, occupancy, sweep, plan, precommit and cellular preparation verify phase-specific rollback including counters and RNG. |
| Matter and occupancy | Count each material and descriptor substance; no duplicate/lost matter, held geometry present, no cellular overlap. |
| Large stack | Measure active and held contact stacks, residual penetration, bounded cost and sleeping no-HELD regression. |
| Automatic detachment / identity | Existing extraction transfers ownership atomically; new/removed IDs invalidate holds safely, descriptor/substance unchanged. |
| Existing cellular coupling | Run prior M4.5a.2–4.1 suites including WATER/GRAVEL/SOIL, F6, revision and recovery tests. |

## Performance and M4.5a.5b gates

Reference, not a new measurement: 134/134/526-cell 64×64 stack, OpenJDK 25, warm settling mean/p95 approximately 13.7/14.8 ms; sleeping 0.68/0.70 ms; all sleep around tick 229. Preserve the no-HELD sleeping fast path and compare repeated identical JVM/scenario runs, reporting variation and any regression. Separately time normal tick, initial SWEPT failure, each HELD retry, sustained HELD, release trial, and a large HELD contact stack; record p50/p95/max, allocations, contact/sweep/occupancy work, candidate count, successes/failures, world size and warmup. Do not average recovery into normal ticks or claim frame-rate compliance without data.

Implementation order proposed: (1) structured obstruction and comprehensive checkpoint/phase tests; (2) held constraint and effective masses with headless contact/rollback tests; (3) full retry and cumulative budgets, occupancy and publication; (4) atomic cellular phase and release/invalidation; (5) diagnostics, regression suite and benchmarks. Gate integration on all matrix invariants, deterministic failure injection and representative interactive verification. Risks still requiring proof include discrete collision tunnelling, residual solver penetration, reaction energy/artifical support, event locality, stale revisions, memory bounds and callback atomicity. This contract is ready as an implementation **plan**, not evidence that M4.5a.5b is safe or feasible at target performance.
