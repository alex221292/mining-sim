# M4.5b.1 — settled-rock ownership foundation

This substage provides ownership metadata and bond separation only. **Bodies do not settle, become World cells, or re-detach yet.** `SettledRockRegistry` is not installed in the interactive session; its package-private `registerExisting` is a narrow metadata fixture/structural building block, not a rigid-to-static transfer or a safe public way to relabel arbitrary rock. A future settling transaction must establish provenance and exclusive ownership and atomically publish World cells, registry, body removal and occupancy. No such transaction or claim of mass transfer is made here.

World remains authoritative for cell material. Each registry entry stores a stable per-registry ID, source fragment ID, immutable placed descriptor and origin, remaining cell count and integer mg, generation and integrity. The descriptor retains substance and original geometry; `cells(id)` filters it through the current ownership index for live cells in row-major order. Cell removal clears ownership, subtracts the substance-specific cell mass, and marks the record damaged/removed. Internal bond break marks damage without changing mass. Splitting, mining-resource payout and recreation of fragments are not implemented. The legacy generic-STONE `ExtractionPlanner` explicitly rejects owned cells as `SETTLED_OWNERSHIP`, preventing automatic extraction from silently changing marble/granite to generic stone; M4.5b.3 must implement substance-preserving re-detachment.

`RockConnectivity` remains the sole World change sink. With an attached registry, intact bonds exist only between STONE cells with the same ownership ID; ID zero is ordinary rock. Different settled IDs and settled-to-ordinary contacts are `ABSENT`, including for component traversal and bond breaking. BEDROCK contact of a settled cell is not a rock bond or a foundation-connected component; later settling must separately verify mechanical support. An ownership change marks topology pending and conservatively invalidates bond incarnations; existing broken internal bonds cannot be silently healed by registration. World edits update ownership through the authoritative sink. Replacing or reattaching that sink while live ownership exists is refused to avoid losing substance history and broken bonds; clearing World removes live ownership. As with existing World notifications, single-owner, non-throwing callback contracts apply.

The index is a dense `long[]`, exactly 960,000 payload bytes for 400×300, excluding Java array header and per-rock metadata. `SettledOwnershipBenchmark` on OpenJDK 25.0.5, 400×300, 100 single-cell records, three sequential 5-million row-major lookups yielded **3.049, 2.822, 1.802 ns/lookup**; these are microbenchmark observations, not whole-tick performance or a sparse-index comparison. Ownership registration is bounded by configured rock and cell limits, with binary search over the descriptor for adjacency. Registry history retains removed records and consumes the configured record capacity; no compaction, persistence or cross-session ID stability is provided. If a revision/generation is exhausted during a World callback, subsequent registry reads fail explicitly rather than return a silently stale token; a new session is required.

`gradlew.bat test build` covers ownership boundaries, generic/settled and settled/settled bonds, BEDROCK semantics, material identity and integer mass, partial removal, bond damage, veto of unsafe extractor, sink replacement, chunk seam, topology invalidation and deterministic replay. Existing regression tests also run. Future M4.5b.2 must implement bounded placement, stability and atomic transfer; M4.5b.3 must implement provenance-safe mining, splitting and re-detachment before sandbox integration. No rigid body is removed, no SAT/tick improvement is claimed, and no Swing scenario was verified in this substage.
